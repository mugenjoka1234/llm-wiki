# Release notes

One folder per release, generated by the `writing-release-notes` skill. Each folder holds `release-notes.md` (a "For the team" and a "For stakeholders" section) and `shipped-changes.json` (validated against the ship-to-signal spec).

| Release | Date | Theme |
|---|---|---|
| [v0.3.18](v0.3.18/release-notes.md) | 2026-07-27 | Scaffolding UX, the team-reporting overhaul, and a skill-chaining audit |
| [v0.3.0](v0.3.0/release-notes.md) | 2026-07-13 | Guided team staffing + layered personas |
| [v0.2.0](v0.2.0/release-notes.md) | 2026-07-12 | Initial public release — the wiki + the factory |

**Maintaining these:** tag each release (`git tag v0.x.y`), then run the `writing-release-notes` skill on the last-two-tags range; it writes the next `signals/releases/<tag>/` folder.
